# التجربة على خادم حقيقي

المنصة مكتملة ومختبَرة محلياً. هذا الدليل هو الخطوة الأخيرة: تشغيلها على خادم المؤسسة بأرشيفها الفعلي وبيانات اعتماد حقيقية، والتحقق من كل وظيفة بمعيار قبول واضح قبل فتح الموقع للجمهور.

المدة المقترحة: أسبوعان. الأسبوع الأول على نطاق فرعي تجريبي (`beta.example.org`) لا يعرفه الجمهور، والثاني بالتوازي مع الموقع الحالي.

---

## 0. قبل البدء: ما يلزم من المؤسسة

| البند | من أين | ملاحظة |
|---|---|---|
| خادم Linux (Ubuntu 24.04 أو Debian 12) | مزوّد الاستضافة | 2 نواة، 4 غيغابايت ذاكرة، قرص 80 غيغابايت أو أكثر حسب حجم صور الأرشيف |
| نطاق فرعي للتجربة | إدارة DNS | سجل A يشير إلى الخادم |
| ملف تصدير الأرشيف | ووردبريس: أدوات ← تصدير ← كل المحتوى | أو JSON Lines من النظام الحالي (الصيغة في README) |
| بوت تيليجرام وقناة تجريبية | ‎@BotFather‎ | أضف البوت مشرفاً في قناة خاصة للتجربة أولاً |
| حساب WhatsApp Business Cloud | Meta Business Manager | رمز دائم، ومعرّف رقم الهاتف، وقالب رسالة معتمد بمتغيرين |
| خادم بريد للنشرة | مزوّد SMTP | مع ضبط SPF وDKIM للنطاق حتى لا تذهب النشرة إلى المزعج |
| مكان آمن للمفتاح الخاص للنسخ | خارج الخادم | حاسوب غير متصل، أو خزنة مدير كلمات مرور للمؤسسة |
| قائمة الطاقم ورتبهم وأقسامهم | رئاسة التحرير | لإنشاء الحسابات |

## 1. التثبيت (اليوم الأول)

```bash
sudo apt install -y docker.io docker-compose-v2 git
git clone <repo> /opt/arcms && cd /opt/arcms
cp .env.example .env && chmod 600 .env
docker compose build
docker compose run --rm web arcms_keys          # انسخ الناتج إلى .env
nano .env                                       # النطاق، كلمة مرور القاعدة، البريد، تيليجرام، واتساب
```

مفتاح النسخ الاحتياطي (يُولَّد مرة واحدة):

```bash
docker compose run --rm web arcms_backup_keygen --private-out /data/backups/backup-private.key
docker compose cp web:/data/backups/backup-private.key ./backup-private.key   # أو انسخه من المجلد مباشرة
# انقل backup-private.key إلى المكان الآمن ثم احذفه من الخادم:
shred -u ./backup-private.key
# وضع السطر ARCMS_BACKUP_PUBLIC_KEY=... في .env
```

التشغيل والتهيئة:

```bash
docker compose up -d
docker compose exec web python manage.py arcms_setup --preset palestine \
    --site-name "اسم المؤسسة" --short-name "الاسم" --admin-username admin --admin-email it@example.org
docker compose exec web python manage.py arcms_check
```

**معيار القبول**: الموقع يفتح على `https://beta.example.org` بشهادة صالحة، و`arcms_check` لا يُظهر أي «خلل» عدا القنوات غير المضبوطة بعد.

## 2. الهوية وبنية الموقع (اليوم الثاني)

من غرفة التحرير بحساب المدير (سيُطلب تفعيل التحقق الثنائي عند أول دخول):

1. **إعدادات الموقع**: الاسم، الشعار (نسخة فاتحة وداكنة)، الألوان، الخطوط، أسماء الأشهر ورسم الأرقام بحسب أسلوب المؤسسة، التاريخ الهجري، روابط التواصل.
2. **الأقسام**: عدّل أقسام القالب لتطابق أقسام الموقع الحالي، وحدّد طاقم كل قسم.
3. **القوائم والصفحة الرئيسية**: رتّب الكتل كما في الموقع الحالي ([دليل بناء الموقع](SITE-BUILDER.md)).
4. **الصفحات الثابتة**: من نحن، سياسة الخصوصية، اتصل بنا.

**معيار القبول**: رئيس التحرير يراجع الواجهة على الحاسوب والجوال ويوافق على الهوية.

## 3. الأرشيف (الأيام 3-5)

```bash
# ارفع ملف التصدير إلى الخادم ثم انسخه إلى الحاوية
docker compose cp export.xml web:/data/imports/export.xml

# تجربة دون حفظ: كم مادة ستُستورد؟
docker compose exec web python manage.py arcms_import wxr /data/imports/export.xml --dry-run

# استيراد عيّنة أولاً للتحقق من الأقسام وأنواع المواد
docker compose exec web python manage.py arcms_import wxr /data/imports/export.xml --limit 200 --download-media \
    --kind-map "مقالات=opinion,فيديو=video,تقارير=report,ترجمات=translation"

# ثم الأرشيف كاملاً (يمكن إعادته بأمان: المواد الموجودة تُحدَّث ولا تتكرر)
docker compose exec web python manage.py arcms_import wxr /data/imports/export.xml --download-media
docker compose exec web python manage.py arcms_reindex
```

الاستيراد يعمل على دفعات، ويُسجَّل في «استيراد الأرشيف» بعدد المواد الجديدة والمحدَّثة والأخطاء. الصور تُنزَّل وتُنزع بياناتها المخفية، وتُحوَّل روابط الموقع القديم بتحويل دائم.

**معايير القبول**:
- عدد المواد المنشورة يطابق الموقع القديم (الفرق = مسودات أو أنواع غير «مقالة»).
- 20 رابطاً قديماً عشوائياً (من محركات البحث ومواقع التواصل) تحوّل إلى المادة الصحيحة. للاختبار: `curl -sI https://beta.example.org/<المسار-القديم>` يعيد `301`.
- البحث عن 10 كلمات يعرف المحررون أين وردت (بصيغها المختلفة) يجد المواد المتوقعة.
- عيّنة من الصور لا تحمل بيانات مخفية: `exiftool` على ملف من `/data/media` لا يُظهر GPS أو طراز الجهاز.
- وقت فتح الصفحة الرئيسية وصفحة مادة أقل من ثانية.

## 4. الطاقم والتحقق الثنائي (اليوم 6)

1. أنشئ حساب كل صحفي من «المستخدمون والرتب» بكلمة مرور مؤقتة، وحدّد رتبته وأقسامه.
2. في جلسة قصيرة مع الطاقم: كل شخص يدخل، يغيّر كلمة المرور، يفعّل التحقق الثنائي بتطبيق على هاتفه، **ويحفظ رموز الاسترداد**.
3. اشرح إجراء فقدان الهاتف: رمز استرداد، أو مدير النظام يعيد الضبط بعد التحقق من الهوية شخصياً.

**معايير القبول**: `arcms_check` يُظهر «كل من يلزمه التحقق الثنائي فعّله»، وسجل التدقيق يُظهر دخول كل مستخدم.

**صندوق المعلومات**: قرّر مع رئيس التحرير أين يُنشر: على الموقع نفسه (`/tips/`)، أو على نطاق مستقل، أو عنوان ‎.onion‎ عبر Tor (الأسلم إن كان في الموقع إعلانات من طرف ثالث؛ انظر `deploy/caddy-sites`). أرسل بلاغاً تجريبياً بصورة من هاتف، وتأكد أن رئيس التحرير يراه بلا بيانات الموقع، وأن الرد يصل إلى صفحة المتابعة بالرمز.

## 5. دورة الخبر كاملة (اليوم 7)

سيناريو يُنفَّذ بأشخاص حقيقيين وقناة تيليجرام تجريبية:

| الخطوة | من | المتوقع |
|---|---|---|
| يكتب خبراً بصورة من هاتفه | مراسل | تظهر رسالة «نُزع من هذه الصورة: إحداثيات GPS…» |
| يرسله للمراجعة | مراسل | يظهر في «بانتظار مراجعتك» عند المحرر |
| يعيده بملاحظة | محرر | يظهر للمراسل «أُعيدت إليك مادة» مع الملاحظة |
| يعدّل ويعيد الإرسال، فيعتمده المحرر | | الحالة «معتمدة للنشر» |
| ينشره | رئيس القسم | يظهر على الموقع خلال ثوانٍ، ويصل إلى قناة تيليجرام التجريبية بالرابط المختصر |
| يحاول نشر مادته دون مراجعة | رئيس القسم | يُمنع برسالة تشرح السبب |
| يجدول مادة بعد 10 دقائق | رئيس القسم | تُنشر آلياً في موعدها |
| ينشر عاجلاً | رئيس التحرير | يظهر في الشريط ويصل إشعار المتصفح لمن فعّل الجرس |
| يفتح تغطية مباشرة ويضيف تحديثات | محرر | تظهر عند قارئ الصفحة المفتوحة دون إعادة تحميل |
| يضيف ملاحظة مصدر سرية | مراسل | لا يراها المحرر الآخر، ويراها رئيس التحرير |

**معيار القبول**: كل الخطوات تنجح، وسجل التدقيق يُظهر كل خطوة باسم فاعلها ووقتها.

## 6. القنوات ببيانات الاعتماد الفعلية (اليوم 8)

إن كانت للمؤسسة صفحة فيسبوك وحساب إكس: ضع رمز الصفحة (Page Access Token بصلاحية `pages_manage_posts`) ومفاتيح تطبيق إكس (قراءة وكتابة) في ملف البيئة، ثم «اختبار الاتصال» من التوزيع، وانشر مادة تجريبية وتأكد من ظهورها بالرابط المختصر.

```bash
docker compose exec web python manage.py arcms_check --live
```

1. **تيليجرام**: في «التوزيع ← تيليجرام» ضع معرّف القناة التجريبية، ثم «اختبار الاتصال». بعد نجاح الأسبوع الأول بدّلها بالقناة الرسمية.
2. **واتساب**: أضف أرقام الفريق فقط أولاً (بموافقتهم)، وانشر مادة معلَّمة «واتساب». تحقق من وصول القالب.
3. **إشعارات المتصفح**: فعّل القناة، ثم من الموقع اضغط الجرس في متصفح حاسوب وهاتف أندرويد، وانشر عاجلاً.
4. **النشرة**: اشترك ببريدين (Gmail وOutlook)، أكّد الاشتراك، ثم «معاينة نشرة اليوم» و«إرسال الآن». تحقق أنها لم تذهب إلى المزعج، وأن رابط الإلغاء يعمل.

**معيار القبول**: كل قناة تُظهر «أُرسلت» في سجل الإرسال، ولا مهام فاشلة في `arcms_check`.

## 7. النسخ الاحتياطي: اختبار الاستعادة (اليوم 9) — إلزامي

قبل الاختبار: اضبط النسخة خارج الخادم (`ARCMS_OFFSITE_*`) بمفتاح وصول لا يملك الحذف، وتأكد من ظهور «رُفعت» بجانب النسخة في صفحة النسخ الاحتياطي، ثم نزّل النسخة من التخزين البعيد نفسه واستعد منها على خادم آخر.

نسخة لم تُجرَّب استعادتها ليست نسخة.

```bash
docker compose exec web python manage.py arcms_backup
docker compose cp web:/data/backups/arcms-<التاريخ>.arcbak ./
```

على **خادم آخر** (أو حاسوب) بتثبيت جديد:

```bash
docker compose up -d db web
docker compose cp arcms-<التاريخ>.arcbak web:/data/backups/
docker compose cp backup-private.key web:/tmp/k.key       # من المكان الآمن، ثم احذفه بعد الاستعادة
docker compose exec web python manage.py arcms_restore /data/backups/arcms-<التاريخ>.arcbak --key /tmp/k.key --verify-only
docker compose exec web python manage.py arcms_restore /data/backups/arcms-<التاريخ>.arcbak --key /tmp/k.key --yes
docker compose exec web python manage.py migrate && docker compose exec web python manage.py arcms_reindex
docker compose exec web python manage.py arcms_audit_verify
```

**معايير القبول**: عدد المواد والصور يطابق الأصل، والبحث يعمل، وسلسلة التدقيق سليمة، والدخول يعمل بالتحقق الثنائي نفسه. ثم انسخ ملفات `.arcbak` دورياً إلى مكان خارج الخادم (هي مشفّرة؛ يمكن حفظها في أي تخزين سحابي).

## 8. الضغط والأداء (اليوم 10)

```bash
# من جهاز خارجي (لا من الخادم نفسه): إشعار عاجل يأتي بعشرة آلاف قارئ خلال عشر ثوانٍ
pip install -r loadtest/requirements.txt
python loadtest/readers.py spike --base https://beta.example.org --readers 10000 --window 10 --path "/post/<رقم>/<الرابط>" --procs 4
# ويوم مزدحم: عشرة آلاف قارئ يتنقلون دقيقتين
python loadtest/readers.py browse --base https://beta.example.org --readers 10000 --duration 120 --procs 4
```

صفحات القرّاء مخزّنة (30 ثانية افتراضياً، وتتجدد فور النشر)، والملفات الثابتة يقدّمها Caddy، وRedis يعمل مع Docker. نتائج قياسنا وما يعنيه كل رقم في [LOADTEST.md](LOADTEST.md). لحدث استثنائي: زِد `ARCMS_WEB_WORKERS` (عملية لكل نواة)، أو استعمل nginx بذاكرة الصفحات (`deploy/nginx/arcms.conf`).

**معيار القبول**: 100% من الصفحات، وp99 للصفحة أقل من ثانيتين في سيناريو الإشعار، ولا أخطاء 5xx في الصفحات.

## 9. أسبوع التشغيل الموازي (الأيام 11-14)

- الطاقم ينشر في المنصة الجديدة بالتوازي مع القديمة (أو ينقل الأخبار المهمة فقط).
- راجع يومياً: «فحص الجاهزية»، و«سجل الإرسال»، و«سجل التدقيق» (محاولات الدخول الفاشلة)، و«الجمهور».
- اجمع ملاحظات المحررين حول الصياغة والتواريخ والبحث.

## 10. الانتقال

1. استيراد أخير لما نُشر في النظام القديم منذ الاستيراد الأول (`arcms_import` يحدّث ولا يكرر).
2. غيّر `ARCMS_DOMAIN` و`ARCMS_SITE_URL` و`ARCMS_ALLOWED_HOSTS` إلى النطاق الرئيسي، ووجّه DNS، ثم `docker compose up -d`.
3. قدّم خريطة الموقع `https://example.org/sitemap.xml` وخريطة الأخبار `news-sitemap.xml` في Google Search Console.
4. بدّل قناة تيليجرام التجريبية بالرسمية.
5. شغّل `arcms_check --live` مرة أخيرة.

## الصيانة الدورية

| متى | ماذا |
|---|---|
| يومياً (آلياً) | نسخة مشفّرة الساعة 3 فجراً، تدوير النسخ (آخر 14)، حذف مفاتيح القياس اليومية |
| أسبوعياً | نسخ ملفات `.arcbak` إلى خارج الخادم؛ مراجعة «فحص الجاهزية» |
| شهرياً | تجربة استعادة على خادم آخر؛ مراجعة المستخدمين المعطّلين؛ تحديث الصورة: `git pull && docker compose build && docker compose up -d` |
| عند مغادرة موظف | تعطيل حسابه فوراً (لا حذفه: يبقى اسمه في سجل التدقيق) |
